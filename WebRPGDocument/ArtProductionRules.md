# 美術製作規範

- 設計狀態：部分已核定；風格方向、UI 基礎色票與[挑戰介面配置](AdventureUI.md)依使用者指定，其餘製作細節待核定。
- 實作狀態：部分實作；單人挑戰 UI 已套用八色色票與挑戰介面配置，角色仍使用佔位標記，其餘資產未確認。
- 適用範圍：遊戲新增或修改的 UI、圖示、角色、怪物、場景、道具與視覺特效；既有資產不因本文件自動要求全面重製。
- 用途：統一美術方向，作為設計、製作與驗收的依據。

## 風格定位

- 1：本專案為 2D 多人自動戰鬥爬塔 Roguelike 遊戲，畫面大部分由 UI 組成；以中世紀黑暗奇幻為主要美術風格，呈現陰暗、冷峻、危險與神祕的氛圍。
- 2：整體採極簡表現，以清楚的輪廓、明暗層次與留白建立辨識度，避免裝飾堆疊。
- 3：美術外觀維持本文件指定的黑暗奇幻、極簡與藍黑底色。
- 4：CLI 風格僅占極少部分，可用於紀錄、短標籤或數值排列；不延伸成整體終端機外觀，也不據此要求玩家輸入指令。
- 5：風格發生衝突時，優先確保資訊可讀與操作辨識，再維持黑暗奇幻氛圍，最後才加入裝飾。

## 黑白基底與強調色

- 6：UI 以接近黑色、略帶藍色的深色為底，不使用純黑（#000000）或中性深灰；以白色為主要文字，透過同色系的明度差異區分面板與層級，維持黑白對比的主要視覺語言。
- 7：次要文字可使用較柔和的灰白色，但不得因過暗而難以閱讀。
- 8：框線採灰白色細框；以亮度差異區分一般、互動與選取狀態，避免所有邊框同時搶眼。
- 9：綠、紅、紫、藍、黃可作為局部強調色，用於需要注意的狀態、資訊或特效；大面積背景維持略帶藍色的近黑基底，一般正文維持白色與灰白色。基底的藍色須克制，與藍色強調資訊保持明顯區別。
- 10：全專案 UI 共用色票不得超過 8 色（含），涵蓋底色、面板、文字、框線、圖示、強調色與各互動狀態；不同明度的指定色碼分別計數。插圖本身的色彩，以及反鋸齒、透明混合等渲染產生的過渡色不計入。同一畫面只強調必要資訊，避免多種高飽和色平均分布，削弱主次關係。
- 11：同一語意的顏色須跨畫面一致；具體色彩語意與色碼核定前，不自行建立生命、品質、陣營等固定對應。
- 12：重要狀態須搭配文字、圖示、輪廓或符號，不能僅靠顏色辨識。

### UI 基礎色票

- 適用範圍：`WebRPG/Assets/WebRPG/` 內新增或調整的 UI 配色。
- 來源：[ChatRoomCanvas prefab](../WebRPG/Assets/WebRPG/Prefabs/ChatRoomCanvas.prefab) 的背景、文字與互動狀態，以及其引用的 [FantasyUIFrame prefab](../WebRPG/Assets/WebRPG/Prefabs/FantasyUIFrame.prefab) 框線。

| 控制項一般底色 | `#292E38` | 41, 46, 56 | Button／InputField 的 Normal、LogoMark |
| 指向底色、目前聊天導覽項目底色 | `#3D4552` | 61, 69, 82 | Highlighted、ChatNavigationButton 的 Normal |
| 細框、選取狀態、輸入文字選取背景 | `#737373` | 115, 115, 115 | FantasyUIFrame、Outline、Selected、SelectionColor |

## UI 與排版

- 13：面板以簡潔幾何結構、細框與一致對齊建立秩序；避免厚重雕花框、繁複捲軸與大面積仿舊材質。
- 14：全專案 UI 資訊統一使用大、中、小三種字級建立層級：大字級用於頁面主標題與核心摘要，中字級用於區塊標題，小字級用於一般內容、欄位、按鈕與紀錄。小字級仍須清楚易讀；同層級資訊共用一致字級，並以字重、間距與明暗輔助區分，不另增字級。同類標題、欄位、按鈕與列表須使用一致樣式。
- 15：一般文字優先使用清楚易讀、支援繁體中文的字體；裝飾字體僅用於少量標題，不用於長文與關鍵數值。
- 16：CLI 元素可採等寬數字、簡短前綴或整齊排列的紀錄文字；避免全畫面 ASCII 框線、持續閃爍游標與逐字輸出拖慢閱讀。
- 17：按鈕與可互動項目須能辨識一般、指向、按下、選取及停用等適用狀態；支援鍵盤導覽時，須提供清楚的焦點標示。
- 18：停用狀態不得只靠降低透明度表現到無法閱讀；必要時以文字說明不可操作的原因。
- 19：背景插圖、紋理與特效不得干擾文字；資訊面板須提供足夠穩定的深色底。

## 圖示、角色與場景

- 20：圖示以簡化輪廓及有限細節表達用途；同組圖示維持一致的線條、視覺重量與明暗處理。
- 21：角色、怪物與道具優先從中世紀武器、防具、服裝與黑暗奇幻符號建立題材辨識；避免混入現代科技或科幻造型。
- 22：黑暗奇幻氛圍可透過殘破石造、鏽蝕金屬、枯木、骨骸與神祕符號表現；這些是可選語彙，不要求每項資產全部使用。
- 23：角色與怪物主要配合 UI，以頭像、圖示或局部插圖呈現；在實際面板尺寸下須可辨識，不以增加細碎紋理取代辨識度。
- 24：場景美術以區域插圖、面板背景或局部氛圍圖支援 UI，不預設需要可自由移動的大型場景；場景中的地點、可操作項目與危險資訊須清楚可辨識。
- 25：彩色魔法、道具或環境光僅作局部焦點，並遵守統一的強調色語意。
- 26：角色、怪物、場景與道具以 2D 畫面呈現；像素、手繪、向量或其他具體表現技法尚未決定，核定前不得將其中一種視為全專案既定規格。

## 特效與動態

- 27：動態以傳達操作、戰鬥與狀態變化為目的，維持短促、克制且清楚的回饋。
- 28：發光、粒子與色彩爆發集中在需要強調的事件，避免常駐效果淹沒略帶藍色的近黑基底與細框。
- 29：關鍵文字、數值及操作區域在特效播放期間仍須可辨識；避免以持續閃爍作為一般裝飾。

## 製作與交付

- 30：製作前須確認資產用途、顯示尺寸、背景、必要狀態與是否需要透明背景；未定項目先記錄，避免直接擴充為通用規格。
- 31：同組資產須維持一致比例、留白、線條與細節密度，並在預期顯示尺寸下檢查辨識度。
- 32：資產須放回代表性遊戲畫面檢查，不能只以單張放大預覽判定完成。
- 33：交付時記錄資產用途、版本、來源及使用授權；使用外部素材時須確認可用範圍。
- 34：實際 Unity 匯入與設定依 Unity 規則及另行核定的資產規格處理；本文件不直接指定匯入參數。

## 挑戰介面與資訊呈現

- 35：挑戰介面的地圖、上方本機玩家數值、中央角色橫列、下方技能與懸停行為，以[挑戰介面](AdventureUI.md)為單一規格來源；右側常駐紀錄亦依該文件。窄畫面的排列與捲動亦依該文件，不套用側邊導覽或單欄卡片配置。
- 36：主要內容以面板、卡片、列表與數值欄位組織；同類活動維持一致的資訊位置，讓玩家容易比較條件、進度與結果。
- 37：時間與進度資訊優先以讀條搭配文字呈現；生命與普攻／技能倒數的具體顯示依[挑戰介面](AdventureUI.md)。不在美術規範中新增離線收益等玩法規則。
- 38：極簡指減少裝飾與重複資訊，不以過度留白或大量彈窗隱藏常用資訊；插圖與動畫須配合資訊版面，不占據主要閱讀與操作空間。

## 驗收情境

- 對應規則 1～5：主要畫面以 UI 為主，可辨識中世紀黑暗奇幻氛圍的資訊組織，CLI 細節不主導整體外觀。
- 對應規則 6～12：全專案 UI 共用色票不超過 8 色（含），各畫面及互動狀態均使用該色票；一般畫面以黑白灰為主，彩色能指向需要注意的資訊；轉為灰階後仍可判斷重要狀態。
- 對應規則 13～19：UI 資訊僅使用大、中、小三種字級，層級一致且最小字級仍可讀；細框清楚，適用的互動狀態可辨識，背景不干擾閱讀。
- 對應規則 20～26：圖示、角色與怪物在實際面板尺寸下可辨識，區域插圖與背景不干擾操作資訊。
- 對應規則 27～29：特效播放時仍可閱讀關鍵資訊並辨識操作區域。
- 對應規則 30～34：交付內容可確認用途與來源，並完成代表性畫面的尺寸與背景檢查。
- 對應規則 35～38：挑戰介面符合專屬文件的驗收情境；上方生命以文字呈現，角色生命與倒數可同時從讀條及文字辨識，常用資訊容易查看，窄畫面下仍可閱讀與操作。
