# 房間聊天

- 設計狀態：草案
- 實作狀態：已實作
- 適用範圍：多人公開與私人房間、同一房間內的多人冒險、房間 WebSocket 通訊。
- 用途：玩家可在房間等待區與冒險紀錄區即時交談，聊天內容不寫入資料庫。

## 規則

- 1：建立或加入成功後進入獨立房間頁，在該頁紀錄區底部提供文字輸入欄與送出按鈕。頁面切換依[房間大廳規則](MultiplayerLobby.md#規則)。冒險開始後，輸入欄移至右側常駐紀錄區，地圖、戰鬥與結算皆可聊天。大廳瀏覽頁與單人冒險沒有聊天輸入欄。
- 2：同一房間從等待、冒險到結算共用一個聊天頻道。進入冒險時帶入本機已接收的房間聊天，接著將房間聊天、房內事件及冒險紀錄依本機收到或產生的順序逐筆顯示於同一份可捲動紀錄。多人冒險合計保留最近 80 筆。聊天列標示發言者，所有玩家輸入皆以純文字顯示。編輯文字時保留輸入法操作並阻擋遊戲快捷鍵，按 Enter 確認組字時不得誤送。
- 3：沿用已驗證的房間 WebSocket 連線。伺服器以該連線的目前房間成員身分判斷能否發言，使用登入身分提供發言者名稱。通過驗證的訊息只即時廣播給該房間成員，包含發送者。客戶端收到伺服器廣播後才加入紀錄。聊天封包獨立於戰鬥同步與房間狀態快照。
- 4：新聊天只經連線即時轉送。伺服器不儲存聊天歷史，也不將聊天正文寫入 PostgreSQL、伺服器日誌或其他持久儲存。客戶端僅於記憶體中保留本次房間連線最近 80 筆房間紀錄，包含聊天與房內事件。新加入或重連時不補發舊訊息。離房、斷線或切換房間時清除本機聊天及未送出的文字。
- 5：每則訊息去除前後空白後最多 240 個 UTF-16 碼元。伺服器接受同一連線每秒最多一則，並拒絕空白、控制字元、超長、超頻或無有效房間成員資格的送出請求。被拒絕時只向發送者顯示原因，保留可重試的文字。聊天拒絕與送出失敗不得改變準備狀態或推進冒險。

## 驗收標準

- 對應規則 1～3：A、B 同房，C 在另一房間或房間列表。A 於等待區發言，A、B 各收到一次且 C 收不到。進入冒險後，A、B 可在地圖、戰鬥和結算的紀錄區繼續交談，切換畫面時保留已收聊天，並可辨識聊天與戰鬥紀錄。公開與私人房間各驗證一次。
- 對應規則 2、5：中文組字確認不誤送，輸入期間不觸發技能快捷鍵。富文字標記照原文顯示。空白、超限和冒用他人身分的請求無法以不合法內容或身分廣播。
- 對應規則 3～4：新成員、重連與換房後無舊歷史，已離房連線無法繼續發言。伺服器重啟後無聊天可回補。
- 對應規則 4：驗證房間聊天不讀寫資料庫，也不將訊息正文寫入持久化日誌。
