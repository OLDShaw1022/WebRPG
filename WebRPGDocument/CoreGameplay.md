# 主玩法

- 設計狀態：部分已核定；單人原型範圍、普攻、可設定的地圖列與敵人隊伍抽選已核定，其餘待確認項目不可據此直接實作。
- 實作狀態：部分實作；已完成單人基礎循環，範圍與限制見[單人可玩原型](AdventurePrototype.md)。多人、資料保存與局外成長尚未實作。
- 用途：定義核心循環、玩家目標與主要系統的關係；各系統細節另行定義。

## 玩法摘要

本作為 2D 多人自動戰鬥爬塔 Roguelike。玩家可單人挑戰，或透過房間組成最多 4 人的隊伍，共同對抗電腦 AI 敵人。每場戰鬥由 1～4 名真人玩家對抗 1～4 名 AI 敵人，組隊時敵人數值依公式增加。

每輪挑戰的地圖共分 3 層，採參考《Slay the Spire》的分支節點路線，每層列數與每列可出現的節點種類可個別設定，每層最後皆為 Boss 戰。玩家在普通戰鬥、精英戰鬥、Boss 戰、寶箱、隨機事件與營火節點之間推進，透過技能與遺物組合建立當輪戰鬥能力。玩家血量在同一輪挑戰中跨戰鬥保留，不因進入下一場戰鬥而重置。

每次戰鬥勝利後，玩家從隨機抽出的至多 3 個不重複技能選項中選擇 1 個；可抽選技能不足 3 個時，只顯示實際可抽選的選項，沒有可抽選技能時不再進行技能抽選。每名玩家最多裝備 6 個技能，新技能依取得順序自動裝入技能槽，取得已裝備的同一技能則直接升級；滿槽後只抽選已裝備技能供升級。已有與未有技能的抽選權重分開設定。玩家具有不占技能槽的自動普攻，普攻傷害與獨立倒數由 JSON 設定。每個技能具有各自的倒數時間，於戰鬥開始時開始倒數；倒數結束時自動觸發，使用完畢後重新倒數並持續循環，戰鬥結束後重置倒數。玩家亦可透過地圖寶箱取得提供被動效果的遺物；多人獎勵由各玩家分開抽選。技能與遺物效果另行設計，採可透過 JSON 組裝的模組化效果。

遊戲具有局外成長要素。玩家透過每輪挑戰賺取金幣，也可透過儲值直接購買金幣。局外成長項目、金幣用途與結算方式另行定義。所有遊戲相關設定以 JSON 管理，尚未確定的數值亦須可由 JSON 設定。玩家資料與挑戰資料儲存於資料庫。戰鬥中全隊倒下，或挑戰中任一玩家斷線，皆視為整輪挑戰失敗；暫不製作特別的斷線重連機制。

## 核心循環

局外成長與挑戰準備 → 單人或組隊開始一輪挑戰 → 選擇地圖路線與節點 → 自動戰鬥並在勝利後進行技能三選一，或處理非戰鬥節點 → 挑戰每層 Boss → 結算當輪挑戰與金幣 → 進行局外成長並準備下一輪挑戰。

## 玩家目標

- 短期：完成節點挑戰，管理持續保留的血量，取得或升級技能與獲取遺物。
- 中期：建立技能與遺物的搭配，與隊友合作挑戰各層 Boss。
- 長期：完成三層爬塔挑戰，累積金幣並發展局外成長。

## 主要系統

| 系統 | 在主玩法中的用途 |
| --- | --- |
| 每輪挑戰與血量 | 管理當輪進度及跨戰鬥保留的血量。 |
| 自動戰鬥 | 由真人玩家隊伍對抗 AI 敵人，普攻與技能依各自倒數自動觸發。 |
| 技能選擇與升級 | 戰勝後技能三選一，最多裝備 6 個，重複取得已裝備技能時升級。 |
| 遺物 | 提供被動效果，可從地圖寶箱取得。 |
| 地圖與節點 | 管理三層分支路線、六種節點及各層末尾的 Boss 戰。 |
| 敵人隊伍池與組隊強化 | 以預設的 1～4 名敵人隊伍為單位抽選，並依組隊公式增加敵人數值。 |
| 組隊與房間 | 支援玩家 ID 邀請，以及從房間列表找到公開房間。 |
| 金幣與局外成長 | 每輪挑戰賺取金幣，支援儲值直接購買金幣，並提供局外成長要素。 |
| 遊戲設定資料 | 使用 JSON 管理遊戲相關設定與可組裝的技能、遺物效果，未定數值亦須可設定。 |
| 資料保存 | 將玩家資料與挑戰資料儲存於資料庫。 |

## 規則

- 1：本作為 2D 多人自動戰鬥爬塔 Roguelike，以每輪挑戰為主要遊玩單位。
- 2：每場戰鬥由 1～4 名真人玩家對抗 1～4 名電腦 AI 敵人。
- 3：玩家具有血量；同一輪挑戰中，各場戰鬥之間保留血量，不因開始或結束戰鬥而自動重置。
- 4：戰鬥自動進行；每個已裝備技能具有各自的倒數時間，於戰鬥開始時以完整倒數開始計時。倒數結束時自動觸發，使用完畢後重新倒數，持續循環；戰鬥結束後重置倒數，不將剩餘倒數帶入下一場戰鬥。各技能倒數時間由 JSON 設定。
- 5：戰鬥勝利後的技能抽選，最多提供 3 個不重複的技能選項，由玩家選擇 1 個；可抽選技能不足 3 個時，只顯示實際可抽選的選項，沒有可抽選技能時不再進行技能抽選。
- 6：每名玩家具有 6 個技能槽；取得新技能時依取得順序自動裝入下一個空槽，不需玩家自行設定裝備或排列。取得已裝備的同一技能時，直接升級原技能，不額外占用技能欄位。
- 7：技能裝滿 6 個後，戰後抽選只會抽出該玩家已裝備且尚未滿級的技能，用於升級；所有已裝備技能均滿級、沒有可升級技能時，停止技能抽選。
- 8：玩家血量歸零後，該場戰鬥無法行動；若隊伍獲勝，該玩家以一定血量復活。復活血量由 JSON 設定，此復活不代表全隊血量重置。
- 9：遺物為提供被動效果的道具，玩家可透過開啟地圖上的寶箱取得。
- 10：每輪挑戰的地圖共分 3 層，路線與節點選擇方式參考《Slay the Spire》，每層最後皆設有 Boss 戰。每層列數、每列可出現的節點種類與節點數須可透過 JSON 個別設定。
- 11：地圖節點分為普通戰鬥、精英戰鬥、Boss 戰、寶箱、隨機事件與營火。
- 12：戰鬥敵人以預先設定的一組隊伍為抽選單位，每組包含 1～4 名敵人；抽中後完整採用該組成員與排列，不逐隻抽選後再拼組。各戰鬥節點使用的敵人隊伍池須可由 JSON 設定；各層池內容與權重另行定義。
- 13：多人遊玩採組隊方式，每隊最多 4 名真人玩家；組隊時依公式增加敵人數值，公式與適用數值另行定義。
- 14：玩家可使用其他玩家的玩家 ID 寄出組隊邀請；接受邀請與加入房間的流程另行定義。
- 15：公開房間可在房間列表中找到；房間的加入條件與流程另行定義。
- 16：遊戲具有局外成長要素；具體成長項目、效果及其對每輪挑戰的影響另行定義。
- 17：玩家可透過每輪挑戰賺取金幣，也可透過儲值直接購買金幣；金幣用途、取得數量與結算方式另行定義。
- 18：所有遊戲相關設定須由 JSON 管理，包括玩家初始數值、技能與倒數、技能抽選與升級、遺物、地圖與節點、敵人與敵人池、組隊強化公式與參數、復活血量、房間規則、金幣取得與局外成長設定；尚未確定的數值亦須保留可透過 JSON 設定的能力，不自行將未核定數值定為正式規則。設定結構與載入方式另行定義。
- 19：戰鬥中全隊玩家倒下時，整輪挑戰判定失敗；挑戰中任一玩家斷線時，當輪全隊挑戰亦直接判定失敗。暫不製作特別的斷線重連機制。
- 20：多人遊玩的獎勵由各玩家分開抽選，包括戰後技能選項與寶箱遺物；該場戰鬥倒地的玩家亦可領取獎勵。玩家完成領取後，須等待其他隊友完成選擇與領取，才可繼續挑戰。
- 21：技能抽選須分開設定已有技能與未有技能的權重；已滿級技能不再納入抽選，滿槽時仍遵守規則 7，只抽選已裝備且尚未滿級的技能。
- 22：技能與遺物的具體效果另行設計；效果須採模組化設計，可透過 JSON 組裝效果模組及設定其參數。
- 23：玩家資料與挑戰資料須儲存在資料庫；保存範圍、寫入時機與保存失敗的處理另行定義。
- 24：多人挑戰的地圖節點由隊伍投票選擇；發生平票時，優先採用隊長所投的節點。投票完成條件與逾時處理另行定義。

- 25：玩家具有自動普攻，不占用規則 6 的六個技能槽；傷害與倒數時間由 JSON 設定。普攻在戰鬥開始時以完整倒數開始，觸發後重新倒數，下一場戰鬥不沿用上一場剩餘倒數。

## 驗收情境

- 對應規則 1、2、13：可單人或以 2～4 名真人組隊進行挑戰，每場敵方初始配置為 1～4 名 AI；組隊敵人數值符合核定後的強化公式。
- 對應規則 3：玩家戰鬥結束後剩餘 40 點血量，若未發生恢復或其他血量變動，下一場以 40 點血量開始。
- 對應規則 4：每個技能於戰鬥開始時依各自設定的完整時間倒數，觸發並使用完畢後重新倒數；戰鬥結束後，下一場不沿用上一場剩餘倒數。
- 對應規則 5：技能抽選同次選項不重複；候選技能至少 3 個時顯示 3 個選項，只有 1 或 2 個時則分別顯示 1 或 2 個。
- 對應規則 6：新技能依取得順序自動裝入下一個空槽，無須手動裝備或排列；取得已裝備技能時立即升級，技能數量不增加，總數不超過 6 個。
- 對應規則 7：裝滿 6 個技能後，所有技能選項皆為該玩家已裝備且尚未滿級的技能；全部滿級後，不再進行技能抽選。
- 對應規則 8：一名隊員血量歸零後停止行動；其餘隊員取得勝利後，該隊員依 JSON 設定的復活血量恢復，其他隊員血量不因此重置。
- 對應規則 9：玩家開啟地圖寶箱後可取得遺物，遺物依設定提供被動效果。
- 對應規則 10、11：每輪地圖共有 3 層，每層末尾皆為 Boss 戰；調整各層列數及各列節點池、節點數後，生成地圖符合該列設定，不出現池外節點。
- 對應規則 12：抽出隊伍的成員數為 1～4 名，成員與順序完整符合其中一個允許的預設隊伍；不混入其他隊伍的成員，同一敵人可依隊伍設定重複出現。
- 對應規則 14、15：可用玩家 ID 寄出組隊邀請，公開房間可在房間列表中找到。
- 對應規則 16、17：依核定的結算規則完成挑戰後可取得金幣；完成儲值購買後可取得對應金幣，局外成長效果符合核定設定。
- 對應規則 18：遊戲數值可由 JSON 設定；調整設定後，在規定的載入與生效時機套用，實際效果符合設定內容。
- 對應規則 19：全隊倒下時整輪失敗；挑戰中任一隊員斷線時亦直接判定整輪失敗，不等待重連或透過重連恢復該輪挑戰。
- 對應規則 20：各玩家分別抽取自己的技能選項與寶箱遺物，倒地隊員仍可領獎；已完成領取的玩家須等待其他隊友選擇與領取完成後，才繼續挑戰。
- 對應規則 21：技能抽選設定包含已有與未有技能的獨立權重；未滿槽時依設定抽選，滿槽後不會抽出未裝備技能。
- 對應規則 22：依後續核定的效果模組規格，可透過 JSON 組裝技能或遺物效果並設定參數，執行結果符合組裝內容。
- 對應規則 23：依核定的保存流程寫入資料庫後，可正確讀回玩家與挑戰資料；讀回資料不代表提供斷線續玩機制。
- 對應規則 24：隊員可對下一個地圖節點投票；發生平票時，優先採用隊長所投的節點，作為隊伍共同前往的節點。

- 對應規則 25：只有普攻也能依設定自動造成傷害，技能槽數不受影響；普攻與技能各自計時，下一場以完整普攻倒數開始。

## 待確認

- 每輪挑戰：初始技能組合、通關與同時擊敗的判定、主動退出方式，以及結束後重置或保留的資料；玩家初始數值由 JSON 設定。
- 戰鬥：站位與目標選擇規則、傷害與防禦計算、技能效果，以及同時觸發時的處理順序。
- 技能倒數：無有效目標時的處理；各技能倒數時間由 JSON 設定。
- 技能抽選與升級：抽選池、已有與未有技能權重的套用方式、技能升級效果；權重、升級數值與等級上限由 JSON 設定。
- 多人獎勵：無可領獎勵時如何完成等待流程，以及選擇與領取的逾時處理；逾時數值由 JSON 設定。
- 倒地與復活：復活血量的設定形式，以及是否存在其他復活方式；實際復活血量由 JSON 設定。
- 遺物：效果、取得池、抽選方式、持有上限、重複取得與堆疊規則，以及個人或全隊生效範圍。
- 地圖：各列節點池與節點數的正式內容、分支結構、生成方式、連線方向、是否允許回頭、節點配置限制與跨層流程。
- 節點：普通、精英與 Boss 戰的差異；寶箱內容、隨機事件選項與效果、營火提供的行動及恢復規則。
- 敵人：各層與各類戰鬥的敵人隊伍池內容、抽選權重、跨場重複抽選規則，以及 Boss 隊伍池的正式內容。
- 組隊強化：具體公式、適用數值、計算人數與計算時機，以及允許隊員加入或退出時是否重新計算；公式與數值參數由 JSON 設定。
- 房間與隊伍：公開設定、列表顯示與篩選、邀請有效期與接受方式、滿房處理、隊長權限、準備流程、節點投票的完成條件、事件決策，以及挑戰中是否允許加入或退出。
- 房間例外流程：挑戰開始前的隊長離線、等待逾時與隊伍解散處理；逾時數值由 JSON 設定。
- 局外成長與金幣：成長項目與成本、對當輪的影響、金幣取得來源與數量、通關及失敗時的結算、儲值方案，以及購買金幣與挑戰所得金幣的使用規則。
- 資料保存：玩家 ID、金幣、局外成長與當輪進度的完整保存範圍、資料庫種類與結構、寫入與讀取時機，以及保存失敗的處理。
- JSON 設定：檔案拆分、資料結構、公式表示方式、驗證規則、載入與生效時機，以及是否影響進行中的挑戰。
- 模組化效果：技能與遺物的具體效果、可用模組、組裝格式、觸發條件、目標選擇、執行順序及模組之間的互動規則。
