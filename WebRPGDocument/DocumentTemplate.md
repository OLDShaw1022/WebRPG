# 文件撰寫格式範例

適用範圍：WebRPGDocument 內新增或修改的設計與技術文件。
用途：統一文件結構，讓 AI 能快速辨識需求與閱讀範圍。

## 撰寫原則

- 1：一份文件只描述一個主題；不同系統拆成獨立文件。
- 2：使用明確標題、簡短條列與完整名稱，避免重複描述。
- 3：規則使用數字編號，方便其他文件引用。
- 4：其他主題以相對連結引用，不複製整段內容。
- 5：未決定的內容放入「待確認」，不得自行補成正式規則。
- 6：設計是否核定與功能是否實作分開記錄。
- 7：無關章節可刪除；新增文件後更新 Document Directory.md。
- 8：文件的長期內容與推送後清理要求，依 [AGENTS.md 的文件維護規則](../AGENTS.md#文件維護)。

## 可複製範本

### 系統文件範例

以下使用虛構的背包功能示範，不代表正式需求或實作現況。

```markdown
# 背包系統

- 設計狀態：範例（可用值：範例／待確認／已核定）
- 實作狀態：未確認（可用值：未確認／未實作／部分實作／已實作）
- 用途：定義玩家持有與整理道具的行為。

## 規則

- 1：背包以欄位數限制可存放的道具。
- 2：背包已滿時，拒絕存入新道具並顯示原因。

## 驗收情境

- 對應規則 1：道具占用的欄位數不得超過背包欄位上限。
- 對應規則 2：背包已滿時，存入新道具會被拒絕並顯示原因。

## 相關文件

- 列出實際存在的相對連結，並說明何時需要閱讀；沒有則填「無」。

## 待確認

- 背包欄位數、道具堆疊規則與資料保存方式。
```

### 規範文件範例

以下使用虛構的資源命名規範示範，不代表正式規則。

```markdown
# 資源命名規範

- 適用範圍：`WebRPG/Assets/WebRPG/` 內新增或重新命名的資源檔案。
- 用途：統一資源命名，方便搜尋與維護。

## 規則

- 1：檔名應清楚表達資源用途，避免使用無意義的名稱。
- 2：同類資源使用一致的命名格式。

## 相關文件

- 無。

## 待確認

- 各類資源的命名前綴與大小寫格式。
```
